# Security and privacy

ContextBridge handles user-selected context. Raw transcripts and real context
packages must stay out of public issues, pull requests, fixtures and releases.
The repository's test credentials are explicitly nonfunctional synthetic sentinels.

The Skill excludes credentials and unnecessary sensitive information before
writing deliverables, including previews and source labels. It treats imported
instructions as data, does not scrape accounts, and does not authorize uploads,
contacting others, changing global memory or replacing host instruction files.

The optional Python helper performs no network calls, uses no external packages,
does not delete source material and refuses existing output destinations. It
screens common credential patterns and some sensitive identifiers. This is not a
complete data-loss prevention system. Semantic review and user review remain
necessary, especially for private personal information and unfamiliar tokens.

Using a hosted AI still sends selected input to that host according to its policy.
Do not interpret a local helper as an offline guarantee for the AI workflow.

To report a vulnerability, use GitHub's private vulnerability-reporting option if
it is available. Otherwise open a minimal issue requesting a private contact
route without including an exploit that exposes private data, credentials or
personal transcripts. Do not post a real credential even to demonstrate a bug.

Supported release line: 0.1.x. Reports involving incorrect provenance, loss of a
critical constraint, prompt injection or leaked sensitive data are in scope.
