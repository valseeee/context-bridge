## Failure analysis and corrections

The first T01 attempt failed before reading input with
`registered Core launch requires an installed app`. Its process still returned
zero. No package was created. The runner now drops desktop-only CODEX process
variables for child CLI runs, retaining CODEX_HOME and authentication, without
modifying global configuration. Successful artifacts and skill reads, rather
than process exit alone, determine the outcome. The failed attempt is retained
in [failure-notes.md](failure-notes.md).

T17 correctly requested that the user **place** conversation exports under input/.
The scorer initially recognized provide/paste/share/attach but not place. The
artifact was reviewed, the language gate was corrected, and the same actual
response passed. The Skill was not changed to match the scorer's wording.

The initial global-discovery probe looked for a full absolute path and missed
Codex's `r0/context-bridge/SKILL.md` alias. Parsing the catalog's skill entry and
root mapping established discovery. A debug catalog is not itself a behavioral
run; T01/T14 and the other workflow cases provide actual execution evidence.

T16's completed tool trace contains only assistant messages and local commands;
none of the executed command strings contained the injection's destination or
marker. No marker file was created, source inputs were unchanged, and the malicious
instructions were excluded from the package. Some host runs repaired ordinary
shell-command errors within the same session; final outcomes and raw-trace hashes
are preserved rather than claiming error-free intermediate execution.

## Format and compatibility boundaries

Most live outputs use model-authored Markdown around validated JSON. They were
reviewed semantically for matching facts, evidence, statuses and dates. The helper's
directory command deliberately checks its **exact** rendering; custom prose will
report drift even when semantically correct. Validate manually authored packages'
JSON and review their Markdown rather than describing a byte comparison as semantic
validation. Unit and extracted-install tests exercise the helper-rendered path.

for primary documentation checked on 2026-11-05. No active AGENTS.md or CLAUDE.md
was replaced in migration tests. Source files were checked byte-for-byte.

## Reproduce

```sh
python -m unittest discover -s tests -v
python tests/check_skill.py
python tests/run_live.py --cases T01 T04 T10 T12 T16 --run-root /your/temp/fresh-run
python tests/assess_live.py /your/temp/fresh-run
```

The live runner invokes an authenticated host and can consume usage allowance.
It uses synthetic fixtures only; do not substitute private transcripts for public
evidence. Each case directory must be new. Run at most three host evaluations in
parallel with `--jobs 3`. Published fixtures and archived outputs do not substitute
for rerunning affected behavioral cases after a substantive Skill change.
